## 3. 各方向的具体建议

### P0：交付（最高优先）

1. 提交 T059–T061 与收尾文档（建议按 T059 安全、T060 打包、T061 评审分三个提交）。
2. 推送 `task/m6-verify-hardening`，以 `--no-ff` 合并 `main`，合并前在 `main` 复跑 typecheck/test/build/pack。
3. 发布前按 `docs/PUBLISHING.md` 清理机器路径；`private` 改 `false` 后 `npm publish --access public`；打 `v0.1.0` tag。
4. 发布后 72 小时内保留 unpublish 能力（见 `docs/RELEASE.md` §5）。

### P1：新手流程（最小增量）

- 首启检查清单：预览目标未运行 / Edge 缺失 / origin 未允许时，给出一步可做的动作（已有部分失败态提示，可合并成统一卡片）。
- 发送前检查清单：标注队列为空、预览已 stale、验证未通过时，在发送按钮附近提示（不阻断、不自动发送）。
- 约束：不新增主界面开关；新参数进设置或“更多”；UI 改动需窄/宽截图 + 组件测试 + 手测记录。

### P1.5：多会话隔离（先验证再动手）

- 验证项：两个会话同时开 Studio、右侧栏切换、预览进程归属、标注/历史/`.vibe` 并发写。
- 若冲突：优先做会话隔离（每会话独立 session id / 端口分配），而不是加锁 UI。
- 结论先写进 DEVLOG，再决定是否立项。

### P2：环境检测（必须 SPEC）

- 范围建议：只读检测 Node/pnpm/Edge/端口/目标服务，给出可解释结论与修复命令；**不自动安装、不改 PATH/系统设置**。
- 可行的最小形态：`/vibe doctor` 或验证面板第五项“环境”；输出 ≤ 4 KB，不联网。
- 反例：自动装依赖、自动改代理/防火墙、自动启动服务——不进入本插件。

### P2.5：Agent 协作深化（DSH 层）

- P3 让 AI 多询问：用 preset 指令 + 工具上下文实现“先确认再改”，不写死在 UI。
- P4 token 卫生：提供 `/vibe` 摘要与建议，度量用 `pnpm usage:cc`；不自动压缩/清空。
- 与现有 `vibecoding-studio` 技能合并维护，避免第二套提示词。

### P3：适配器与 B 类能力

- 选择依据：真实用户目标（Vite/Next 最常见 → B03 优先；React Native/移动端 → B09 最后）。
- 每类 adapter 复用 `Target` 契约与 `PreviewService`，不新增第二套预览通道。
- B02 截图附件在找到公开 `InputActions` 附件路径前维持“复制 PNG + 手动粘贴”。

## 4. 持续约束（不因方向变化而放宽）

- 仅本机目标；拒绝 `file:`/`chrome:`/`devtools:`/云元数据/私网。
- 不自动发送标注、不自动批准、不自动提交；截图不是唯一证据。
- host/client 只走 `ctx.connection`；密钥只在 `ctx.credentials`，UI 只读 `describe`。
- 只改 `vibe-dev`；`desktop`/`web` 不动。
- 无 MCP、依赖最小化、无重型运行时依赖。
- 产品级能力先 SPEC/计划，后实现；不夹带。
