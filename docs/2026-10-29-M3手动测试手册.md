# Vibe Studio 手动测试手册（M3 Inspect + Annotation）

> 适用版本：`task/m3-inspect`（T027–T034，G3 GO；基线提交 `c37aeb4`）
> 环境：Windows 11 + Microsoft Edge + Node 24 / pnpm 11；DSH `0.2.1-rc.2`；开发 profile 仅 `vibe-dev`
> 全量走一遍约 35–45 分钟（含三框架源码抽测）
> 覆盖范围：元素拾取与选择器、元素上下文、React/Vue/Svelte 源码定位、标注气泡、标注队列、保存通知、composer 交接、标注历史、4 KB 预算与清理。
> 不重复验收：预览启动/帧率/输入/Console/Network/设置属 M2，仅作为本手册的前置检查；检查 / API 页签仍是占位页。

---

## 1. 一次性准备

### 1.1 构建插件

在仓库根目录 `<repo>`：

```cmd
cd <repo>
pnpm install
pnpm build
```

判断成功：输出里出现 `built lib\index.js` 和 `built lib\client.js`。

> DSH 运行中改代码后必须重新 `pnpm build`、重启 DSH 并刷新页面，否则加载的还是旧 `lib/client.js`。

### 1.2 确认插件已链接进开发 profile

```cmd
<DSH_BIN> --profile vibe-dev --dump-config | findstr vibe-studio
```

看到 `- id: vibe-studio` / `name: dsh-vibecode-studio` 即已就绪。若没有，执行一次：

```cmd
<DSH_BIN> plugin --profile vibe-dev add link:<repo>
```

> 若 `dsh` 不在 PATH 上，请使用 DSH 安装目录中的启动器（Windows 通常是 `bin\dsh.cmd`），并按需设置 `DSH_HOME`。**不要**把包装进 `desktop` / `web` profile。

### 1.3 准备一个真实会话

1. 在 DSH 里新建或打开一个**真实会话**（不是空面板）。
2. composer（对话输入框）可见且可输入。

> 标注交接只写当前会话的草稿；没有 composer 时会退回剪贴板。隔离 Desktop 载体目前点“新建会话”不会建会话，因此本手册以 **Web（vibe-dev）** 为准。

### 1.4 面板宽度

把右栏拖到 **400–500px**，气泡宽 240px、拾取卡片宽 320px，太窄时会被压缩或贴边；这不是缺陷，但会影响观察。

## 2. 启动流程

需要**两个窗口，都保持开着**；源码抽测再按需开第三个窗口。

### 窗口 1：被测页面（fixture）

```cmd
cd <repo>
pnpm fixture:dev
```

成功标志：输出 `Local: http://127.0.0.1:4320/`。浏览器直接打开能看到 “Vibe Studio Fixture” 页面。这个窗口一关，预览就白屏。

### 窗口 1b（可选）：三框架源码 fixture

只在做“源码定位”时启动，端口互不冲突：

```cmd
:: React → 4321
pnpm exec vite fixtures/source/react --config fixtures/source/react/vite.config.js --host 127.0.0.1 --port 4321 --strictPort

:: Vue → 4322
pnpm exec vite fixtures/source/vue --config fixtures/source/vue/vite.config.js --host 127.0.0.1 --port 4322 --strictPort

:: Svelte → 4323
pnpm exec vite fixtures/source/svelte --config fixtures/source/svelte/vite.config.js --host 127.0.0.1 --port 4323 --strictPort
```

看到 `Local: http://127.0.0.1:432x/` 即成功。三个命令各占一个窗口，可以只开需要的那个。

### 窗口 2：DSH

```cmd
<DSH_BIN> --profile vibe-dev --no-open --host 127.0.0.1 --port 4317
```

成功标志：终端打印一行

```text
dsh web: http://127.0.0.1:4317/?token=<一串字符>
```

> 完全就绪前 DSH 不打印任何内容，等这行出现再操作，别重复开实例。

### 打开 Studio

1. 复制带 token 的完整 URL，在浏览器打开。
2. 右侧边栏点 **新标签页** → 选 **Vibe Studio**。
3. 停在 **预览** 页签，地址行填 `http://127.0.0.1:4320`，点 **启动**。
4. 等状态行出现 `● 运行中 · N fps`，画布出现 fixture 页面。

前置检查：画布能点击、输入框能输入（M2 已验收；这里只确认预览可用）。**拾取按钮在预览运行后出现；页面不支持拾取时按钮为禁用态。**

## 3. 详细使用流程

### 3.1 开启拾取

1. 工具栏右侧出现 `⌖` 按钮，悬停提示“拾取元素”（页面不支持拾取时为禁用态，悬停提示会说明原因）。
2. 点一下：按钮变为 `✕`、按下态，画布出现十字光标，画布顶部提示

   ```text
   拾取中：在预览里点击元素 · Esc 取消
   ```

3. 鼠标在画布内移动，元素上出现高亮框（overlay），跟随指针。

- `Esc` 或再点 `✕` 退出拾取；退出后页面恢复正常点击行为。
- **Alt+点击**在未开启拾取时也能直接拾取一个元素（设计如此，方便临时取一个）。

### 3.2 拾取一个元素

1. 拾取开启时，点击画布里的 **Count: N** 按钮（`[data-testid="counter"]`）。
2. 右上角出现卡片 **已拾取元素**：
   - 徽标 **唯一**；
   - 选择器（如 `[data-testid="counter"]` 或 `button[data-testid="counter"]`）；
   - `button` / classes；
   - **位置**：`x, y · 宽×高`；
   - **源码**：`无源码信息`（`fixtures/vite-basic` 没装 inspector 插件，属预期）。
3. 元素旁弹出气泡 **标注这个元素**，textarea 自动聚焦，占位文案：
   `你希望改什么？例如：这个按钮太小`
4. 回到画布看计数：**没有增加**——拾取吞掉了页面自身的点击。

要点：

- 选择器优先 `data-testid` / 唯一 `id`，最后才用 `nth-of-type` 路径；绝大多数元素显示 **唯一**。
- 卡片可整段选中选择器复制；点 `×` 收起卡片和气泡（拾取模式不因此退出）。
- 按 `Esc` 退出拾取后，**已经拾取的卡片仍保留**，直到点 `×` 或保存。
- 连续点击不同元素会更新卡片位置；建议先写完当前意见再点下一个元素。

### 3.3 写意见并保存

1. 在气泡里输入中文，例如：`这个按钮太小，请把内边距改大一点。`
2. 按 **Ctrl+Enter**（Mac 为 Cmd+Enter）或点 **加入标注队列**。
3. 预期：
   - 气泡与拾取卡片消失；
   - 画布右下角出现通知 **已加入标注队列**，带 **发送到对话** / **查看队列** 两个按钮；
   - 拾取模式**仍然开启**（`✕` 仍为按下态），可以直接拾取下一个元素；
   - 标注页签出现数量徽标 `1`。
4. 保存后 **composer 仍为空**，会话里没有新消息——保存不会发送。

边界：

- 空意见点保存 → 气泡底部红字 **先写一句意见。**，不加入队列。
- 在 textarea 按 `Esc` → 取消，不入队。
- 意见最长 2000 字符（`maxLength`），超出的粘贴会被截到 2000。

### 3.4 保存通知 → 发送到对话（G3 的 3 步闭环）

前提：真实会话的 composer 可见。

1. 在刚出现的通知里点 **发送到对话**。
2. 预期：
   - 通知文字变为 **已插入对话草稿，尚未发送。**；
   - **发送到对话** 按钮消失，**查看队列** 保留；
   - 队列徽标减 1（用 DOM 钩子验证时 `[data-vibe-annotation-item]` 减少 1）；
   - composer 里出现一段结构化文本，开头类似：

     ```text
     Annotation a-xxxx-1
     Target: ...
     Created: ...
     Source: element

     Comment:
     这个按钮太小，请把内边距改大一点。

     Element context:
     <untrusted-page-content source="element-context">
     selector: [data-testid="counter"]
     tag: button
     ...
     </untrusted-page-content>
     ```

     若选择器不唯一，`selector` 行会多一个 `(not unique)` 标记。

   - 会话里 **没有新增用户消息**；等 5 秒再看，composer 内容逐字不变。
3. 从点击元素算起的动作数：**点击元素(1) → 输入并保存(2) → 发送到对话(3)**。
   开启拾取是额外第 4 次点击（G3 已按用户确认口径如实记录）。

> 已有草稿时，标注会插在光标处并前置一个空行，不会覆盖你已写的内容；插入后仍要你自己按发送。

### 3.5 标注队列

1. 点通知里的 **查看队列**，或切到 **标注** 页签。
2. 列表最新在前，每条显示：选择器、时间（HH:MM）、源码末段（有源码时）、意见。
3. 操作：
   - **编辑**：进入 textarea，改完点 **保存**；清空后保存提示 **意见不能为空。**，点 **取消** 恢复；
   - **发送到对话**：与通知里的发送同规则，成功才移除，失败保留并显示 **发送失败，请重试。**；
   - **移除**：只移出队列，历史记录不受影响。
4. 切到预览再切回标注：队列仍在；拾取状态也保留（已知行为）。
5. 刷新整个浏览器页面（F5）后重开 Studio：**队列清空**（只存在面板会话内存），历史仍在。

页脚提示固定为：**发送只把意见放进对话，不会替你提交。**

### 3.6 标注历史

正常情况下，每条保存成功的标注会自动写入历史。文件位于 DSH 启动目录下的 `.vibe/annotations/<id>.json`；本手册从仓库根启动 DSH，所以是：

```text
.vibe\annotations\
```

1. **列表**：标注页签下半部“标注历史”，标题右侧是总数；条目显示选择器、日期时间、源码末段、意见。
2. **搜索**：输入意见里的关键词（中文可）→ 只剩匹配项；输入乱码 → **没有匹配结果** + **清空搜索**。
3. **重新打开**：点 **重新打开** → 上方队列多一条，状态 **已重新放入上方队列，尚未发送。**；composer 不变，历史条目不变。
4. **删除**：点 **删除** → 变成 **确认删除** / **取消**；确认后状态 **标注已删除。**，列表减 1，磁盘文件消失。取消则不变。
5. **重启持久化**：Ctrl+C 停 DSH，按 §2 重启、刷新页面、重开 Studio → 历史仍在（队列为空）。
6. **坏文件不崩溃**（可选，务必只删自己创建的文件）：
   1. 新建一个坏文件：

      ```powershell
      Set-Content -Path .vibe\annotations\manual-broken.json -Value '{not json' -Encoding utf8
      ```

   2. 切到别的页签再切回标注（历史重新挂载），预期出现
      **已跳过 1 个无法读取的标注文件。**，正常条目不受影响。
   3. 删除这个文件：

      ```powershell
      Remove-Item .vibe\annotations\manual-broken.json
      ```

   4. 再切一次页签，提示消失。

### 3.7 源码定位（React / Vue / Svelte）

`fixtures/vite-basic` **没有**源码信息，这是设计预期。要验证源码命中，用 §2 的源码 fixture：

1. 启动 React fixture（4321），浏览器先打开 `http://127.0.0.1:4321/` 确认页面正常。
2. 在 Studio 预览地址行填 `http://127.0.0.1:4321`，点 **前往**（同一会话内导航）。
3. 开启拾取，点击 **Primary** 按钮（`#primary-button`）。
4. 预期卡片 **源码** 显示 `App.jsx:17`（行号允许 ±2），源码属性 `data-vibe-pick-source="1"`、`data-vibe-pick-source-via` 非空。
5. 可选：Vue（4322）点 Primary → `App.vue:18`；Svelte（4323）点 Primary → `App.svelte:17`。
6. 回切到 `http://127.0.0.1:4320`，拾取 `Count` 按钮，确认重新显示 **无源码信息** 且拾取不报错。

> 生产构建没有源码元数据，UI 同样显示 **无源码信息**；三框架生产回退已由 `pnpm test:e2e` 覆盖，不必手测。
> React 19 需要在目标项目 dev 构建里启用 `@react-dev-inspector/babel-plugin` 才有一级路径，这是接入方的前置条件。

### 3.8 4 KB 预算与截断（可选）

1. 正常中文意见发送后，在 composer 里 **Ctrl+A / Ctrl+C**，再在 PowerShell 里量字节：

   ```powershell
   $t = Get-Clipboard -Raw
   $t.Length
   [Text.Encoding]::UTF8.GetByteCount($t)
   ```

   预期字节数 **≤ 4096**。
2. 粘贴约 2000 个中文字符再保存、发送，重复测量：仍 ≤ 4096 B。
   已知限制：约 1617 个中文字符后会截断，气泡和 composer 都**没有“已截断”提示**；这是 G3 记录的非阻断项。
3. 在 composer 文本里确认 `<untrusted-page-content source="element-context">` 与 `</untrusted-page-content>` 各只出现一次，元素 HTML 位于两者之间。

> 不要为了测预算清空已有草稿；可以先在临时会话里做，或测完手动删除这段文本。

### 3.9 清理

1. Studio **⋯ 更多 → 停止**，状态回 `空闲`。
2. 关闭窗口 2（DSH）与窗口 1 / 1b（fixture 与源码 fixture）。
3. 只删除本轮自己创建的标注文件：

   ```cmd
   dir .vibe\annotations
   del .vibe\annotations\<本轮 id>.json
   ```

   确认目录为空且没有 `studio.json` 后，才可删除空目录：

   ```cmd
   rmdir .vibe\annotations
   rmdir .vibe
   ```

   **不要**用递归删除；`.vibe/studio.json` 是 M2 的设置文件，要保留。
4. 检查端口与进程（只读）：

   ```powershell
   Get-NetTCPConnection -State Listen -LocalPort 4317,4320,4321,4322,4323 -ErrorAction SilentlyContinue |
     Select-Object LocalPort, OwningProcess

   Get-CimInstance Win32_Process -Filter "Name='msedge.exe'" |
     Where-Object { $_.CommandLine -like '*playwright_chromiumdev_profile*' } |
     Select-Object ProcessId
   ```

   输出为空 = 无残留监听 / 无预览 Edge。

## 6. 正常但容易误判的现象

- **保存后拾取模式不退出**：设计如此，方便连续标注；按 `Esc` 或点 `✕` 退出。
- **`Esc` 后卡片还在**：退出的是拾取模式，不是已拾取结果；点 `×` 收起。
- **通知会消失**：切页签或重开面板后保存通知不再显示，但标注已在队列/历史里，可从标注页发送。
- **队列刷新即清空**：队列只存在面板会话内存；历史写入 `.vibe/annotations`，刷新/重启仍在。
- **`fixtures/vite-basic` 显示“无源码信息”**：该 fixture 没装 dev inspector 插件，不是拾取失败。
- **2000 字意见被截断且无提示**：4 KB 预算的已知限制，G3 记录为非阻断项。
- **“非唯一”很少出现**：选择器会用 `nth-of-type` 路径兜底，普通页面元素通常都是唯一；真出现时按实际记录。
- **标注文本是英文结构、中文意见**：`Annotation` / `Comment:` / `Element context:` 是给 agent 的结构，意见原文保留中文，属设计。
- **Alt+点击没有 hover 高亮**：未开启模式时只有点击后才出结果。
- **“发送到对话”是插入，不是提交**：插入到光标处，已有草稿保留，前置一个空行；仍需用户自己按发送。
- **通知发送成功后按钮消失**：成功态不再显示“发送到对话”，只保留“查看队列”。
- **`.vibe` 位置跟随 DSH 启动目录**：本手册从仓库根启动，故在项目根；换目录启动会写到别处。
- **刚保存时在别的页签数队列为 0**：标注页未挂载时 `[data-vibe-annotation-item]` 不存在，属测量时序。

## 7. 故障排查

| 现象 | 检查 |
|---|---|
| 工具栏没有 `⌖` | 预览是否 `运行中`；页面是否支持拾取（`capabilities.pick`）；面板是否过窄 |
| `⌖` 灰色不可点 | 页面脚本被拒或会话未就绪；看 Console 是否有注入错误 |
| 点击元素没反应/页面自己被点 | 是否真的在拾取态；`Esc` 后重开；确认点的是画布内而不是面板 |
| 没有源码信息 | 目标项目是否 dev 构建并启用对应 inspector 插件；`fixtures/vite-basic` 属预期 |
| 保存后通知没出现 | 是否保存成功（意见非空）；是否刚切过页签（通知会丢，但队列在） |
| 点“发送到对话”提示失败 | composer 是否可见；是否有真实会话；看浏览器 Console 与 DSH 日志 |
| composer 没变化 | 是否点错会话；是否有真实会话（隔离 Desktop 不能新建会话） |
| 队列/历史为空 | 队列刷新即空属预期；历史看 `.vibe/annotations` 是否存在 |
| 历史显示“历史不可用” | 目录权限、`.vibe` 是否为越界链接；重试或重启 DSH |
| 历史提示跳过文件 | `.vibe/annotations` 里有坏 JSON；按 §3.6 只删坏文件 |
| 改了代码没生效 | 重新 `pnpm build`，重启 DSH，刷新页面 |
| 端口被占用 | 4317/4320–4323 是否被上一轮残留；按 §3.9 查监听与进程 |
