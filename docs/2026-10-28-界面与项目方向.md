# 界面与项目方向（2026-10-28）

> 来源：用户《M1界面修改意见》（本地 `M1阶段界面审查/M1界面修改意见.docx`，未入库）+ 2026-10-28 会话讨论。
> 性质：**方向性约束**。后续开发（U01、T027 及 M4/M5）以此为准；与本文冲突的想法先改本文，再写代码。
> 一句话：**画布是主角，参数进设置，复杂调试交给 DSH agent；产品不臃肿，按模块接入。**

---

## 1. 定位与原则

- 目标用户：vibe coding 的**初学者/小白**，希望少学工具、多和 agent 对话。
- 插件职责：把"预览、指认、描述"做简单；把专业调试参数收起来，必要时交给 agent。
- 六条硬原则：
  1. **画布优先**：任何新功能不得以新增常驻工具行/信息行挤压预览画布。
  2. **配置外移**：视口、比例、帧率等参数只放在设置页或"更多"弹层，不进主界面。
  3. **渐进披露**：默认只显示状态、地址、前往/启动；其余操作收进菜单或抽屉。
  4. **引导优先**：空状态、失败状态必须给出下一步操作提示（面向初学者）。
  5. **不臃肿**：优先复用 DSH 能力与 adapter 机制，不把 IDE/工具箱塞进插件。
  6. **安全边界不变**：仅本机目标；不自动发送/批准/提交；页面内容按不可信处理。

## 2. 界面修改方向（Layout v2）

### 2.1 目标布局

```text
┌──────────────────────────────────────────┐
│ ● 运行中 · 25 fps                 ⋯ 更多  │  状态条（单行，24–28px）
├──────────────────────────────────────────┤
│ [ http://127.0.0.1:4320          ] [前往] │  地址行（仅空闲/需要时出现）
├──────────────────────────────────────────┤
│                                          │
│                                          │
│              预览画布（占满剩余空间）       │  主角：100% 宽，保持比例
│                                          │
│                                          │
├──────────────────────────────────────────┤
│  控制台 (2)    网络 (8)                  │  底部 tab（28px，常驻）
└──────────────────────────────────────────┘
  点击 tab → 抽屉从底部覆盖画布（不压缩画布）
```

- 空闲时地址行为：`[地址输入] [启动]`；运行中变为 `[地址输入] [前往] [刷新]`。
- 状态条：状态点 + 状态文字 + fps；点击可展开详情（seq、模式、最近错误）。
- **更多 ⋯**：停止、重启（失败时）、在浏览器打开、视口预设（1280×800 / 1440×900 / 自适应）。
- 控制台 / 网络：底部 tab 显示计数，点开为覆盖层；再次点击或关闭按钮收起。
- 抽屉高度：默认约面板高度的 40%，不改变画布尺寸；画布上的输入层不被抽屉遮挡区域接收事件。

### 2.2 元素处置表

| 现有元素 | 去向 |
|---|---|
| 预览地址输入 | 保留在地址行 |
| 启动 / 前往 | 合并为地址行的主按钮（按状态切换） |
| 刷新 | 地址行图标按钮（仅运行中） |
| 视口宽 / 高 + 应用 | **移到设置页“预览”分组**；主界面只保留“更多 → 视口预设” |
| 在浏览器打开 | 移到“更多”菜单 |
| 停止 / 重启 | “更多”菜单；失败时“重启”提升为画布内提示按钮 |
| 状态行（`状态: 运行中 · 流式 · 帧数: N · #seq · 30 fps`） | 压成单行 `● 运行中 · 25 fps`；详情点开再看 |
| 控制台 / 网络 展开按钮 | 改为底部常驻 tab + 覆盖式抽屉 |
| 空状态长文案 | 保留一句操作提示（例：先填地址点启动） |

### 2.3 初学者引导（随 Layout v2 一起做）

- 空闲画布提示：`输入本地地址（如 http://127.0.0.1:3000）后点“启动”`。
- 启动失败：画布内显示原因摘要 + 三条常见检查（fixture/端口/Edge）+ “重启”。
- 抽屉空状态：`还没有消息。在预览里操作页面后会自动出现。`
- 设置页“预览”分组加说明：`仅影响预览目标页，不改变 DSH 窗口大小。`

### 2.4 U01 验收

- 在右栏宽度 320 / 400 / 500px、窗口高 900px 下：无横向溢出；画布高度 ≥ 面板高度的 60%。
- 主界面常驻行数 ≤ 3（状态条、地址行、底部 tab）；任何参数输入不再常驻。
- 抽屉展开/收起时画布尺寸不变；画布输入（点击/键入/滚动）仍正常。
- 既有功能全部回归通过：P1–P5、V1–V6、I1–I8、C1–C5、N1–N6、L1–L7、S1–S7（见手动测试手册）。
- 帧率不下降（1280×800 下仍约 25 fps）；浏览器 console 0 error。
- 组件测试更新并通过；`pnpm typecheck/test/build` 全绿。

### 2.5 明确不做

- 不做 IDE 式多面板、文件树、代码编辑器。
- 不做手机/设备模拟器（视口预设仅是宽高切换）。
- 不在主界面暴露 CDP/帧率/抓包等专业参数；需要时由 agent 获取或进设置。

## 3. 项目方向

### 3.1 分级

| ID | 方向 | 级别 | 说明 / 约束 |
|---|---|---|---|
| P1 | 新手流程引导 | **近期（并入 U01/后续 UI）** | 首次使用、失败恢复、空状态提示；后续可在发送前加“检查清单” |
| P2 | 一键部署 / 环境检测 | **需立项调研** | 检测 Node/pnpm/端口/依赖，失败要可解释；涉及安装与系统变更，**必须先出 SPEC 并获批准**，不得自动改系统 |
| P3 | 让 AI 多询问再操作 | DSH 层 | 通过 agent 指令/模板与插件提供的上下文实现，不写死在 UI 里 |
| P4 | 减少 token / 上下文清理 | DSH 层 | 提示或工具化（`pnpm usage:cc` 度量）；不自动清空、不自动压缩 |
| P5 | 适配团队工作模式 | 需验证 | 先确认 DSH 团队/多会话下右栏与预览不冲突，再做适配 |
| P6 | 引入 GitHub 成熟 agent 工具 | 需调研 | 按项目规则 GitHub-first：活跃度、许可证、DSH 适配；不整段照搬 |
| P7 | 模块化、避免臃肿 | **持续原则** | 新能力走 adapter/契约扩展；不新增重型运行时依赖 |

### 3.2 方向性约束（防止跑偏）

- **U01 定稿前不改 T027 overlay 的坐标假设**；T027 必须基于 U01 的最终画布几何。
- 任何“新参数/新开关”默认进设置页或“更多”，不得直接加到主界面。
- 产品级能力（P2–P6）必须先更新 SPEC/计划并获批准，不能夹在实现任务里顺手做。
- 保持：仅本机目标、不自动发送/批准/提交、不改 `desktop`/`web` profile、无 MCP、依赖最小化。
- UI 修改后必须同时给：截图（窄/宽两种宽度）+ 组件测试 + 手动回归记录。
