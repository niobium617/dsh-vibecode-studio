## 0. 前置

1. **构建**（`vibe-dev` 是 `link:` 依赖时，改代码后必须重新构建并重启 DSH）：

   ```bash
   pnpm install
   pnpm build        # lib/index.js + lib/agent.js + lib/client.js
   ```

2. **启动**（Windows；关掉旧窗口，旧进程仍载入旧 bundle）：

   ```powershell
   F:\Deepseek-Harness\DH\bin\dsh.cmd --profile vibe-dev
   ```

3. **准备预览目标**（另一个终端）：

   ```bash
   pnpm fixture:dev   # http://127.0.0.1:4320/
   ```

4. **允许该 origin**：右栏 Vibe Studio → **设置 → 允许的 origin**，加入一行：

   ```
   http://127.0.0.1:4320
   ```

   默认只有 `http://localhost`、`http://127.0.0.1`（不带端口），带端口的本地地址必须显式加入。

5. （可选）本次若不手测打包，直接跳到第 1 节；第 6 节需要 `file:` 安装，会临时替换 `link:`。

## 1. 验证面板入口与空态

1. 打开右栏 **新标签页 → Vibe Studio**，进入「预览」页。
2. 查看底部抽屉页签：应有「控制台」「网络」「验证」三个。
3. **不启动预览**时点「验证」：
   - 预期：面板显示「先启动预览再运行检查。」；「运行检查」不可用或点击无效。
4. 启动预览（地址 `http://127.0.0.1:4320/`，点「启动」），等状态行变为 Live。
5. 再点「验证」页签：
   - 预期：显示「尚未运行。」与可点的「运行检查」按钮。

## 2. 全绿基线（四项检查）

1. 预览已 Live，页面正常渲染，且没有人为制造的报错。
2. 点「运行检查」，等待按钮从「检查中…」恢复。
3. 预期：
   - 摘要为 **「全部检查通过」**。
   - 四行结果：**预览目标**（passed）、**页面**（passed，含 DOM 节点数）、**控制台**（passed，`0` 个错误）、**网络**（passed，`0` 个失败）。
   - 结果整体 ≤ 4 KB（超出时面板会提示「证据已裁剪以适配大小限制。」，正常页面不应出现）。

- [ ] 通过　备注：__________

## 3. 失败定位与证据跳转

### 3.1 控制台错误

1. 在预览画布中点击 fixture 的 **Trigger console error** 按钮（按钮会产生一条 `fixture: intentional console error`）。
2. 点「运行检查」。
3. 预期：摘要变为 **「4 项检查中有 1 项未通过」**；**控制台** 行 failed，提示 `1 console error buffered` 一类文案，并列出证据条目。
4. 点该证据条目：
   - 预期：底部抽屉切换到「控制台」，对应错误行滚动到可见位置并**高亮约 2 秒**。
5. 再点同一证据一次：应再次高亮（非首次点击也生效）。

### 3.2 网络 500

1. 在预览画布中点击 fixture 的 **GET /api/boom** 按钮。
2. 点「运行检查」。
3. 预期：**网络** 行 failed，证据含 `GET /api/boom` 与失败状态（500）。
4. 点证据条目：
   - 预期：抽屉切换到「网络」，对应请求行滚动到可见位置并高亮约 2 秒。

### 3.3 多重失败

1. 同时保留 console error 与 500 后再运行。
2. 预期：摘要「4 项检查中有 2 项未通过」，两行各自给出证据；点击任一证据都能跳到对应抽屉。

## 4. 只读边界（不自动修复、不自动发送）

1. 在任何失败状态下，确认验证面板只有「运行检查」与证据跳转，**没有**「修复」「发送给 Agent」「自动重试」等按钮。
2. 运行检查不会改动页面、不会清空 Console/Network 缓冲、不会在对话里生成消息。
3. 检查不会写 `.vibe/annotations`；标注数、历史数在运行前后保持不变。

## 5. 主链路手测（打开 → 预览 → 拾取 → 标注 → 放入对话 → 发送）

1. 确认预览 Live；点「检查」页签，开启拾取。
2. 在画布中点选任意元素 → 气泡出现 → 填写意见 → 保存。
3. 保存通知里点「发送到对话」（或到「标注」页签发送队列条目）。
4. 预期：composer 出现结构化文本草稿，**不会自动发送**；手动点发送后，对话中出现该消息，预览仍可见。
5. （U05 回归）打开「控制台」，确认：
   - React DevTools 一类长消息按正常宽度折行，不再一词一行；
   - 右侧超长来源 URL 以 `…` 省略；
   - 短消息布局不变，抽屉可正常关闭/重开。

## 已知限制（不是缺陷）

- Host 就绪前的 503 轮询会在 Console 留下几条错误；启动完成后新开的验证会是全绿，旧错误不会自动清空（可在控制台点「清空」后再运行）。
- 验证只覆盖目标/页面/Console/网络四项，不做视觉回归、不做断言、不替代 Playwright。
- 验证结果 ≤ 4 KB，证据最多每项 5 条；被裁剪时面板会明确提示。
- 预览/验证只在 `vibe-dev` 手测；`desktop`/`web` 不是安装目标，Desktop 仅在 `.tmp/` 隔离 home 的 profile 副本上做过冒烟。
- 面板只读：不会自动修复、不会自动发送、不会自动提交；标注仍需人工审核与发送。
- soak 的帧率取决于机器负载；G6 记录为 16.1 fps 中位（≥10 fps 达标）。
