# Vibe Studio 手动测试手册（M4 API Workbench）

> 适用版本：`task/m4-api-workbench`（T035–T046，G4 复评 GO；文档基于 `4feba69`）
> 环境：Windows 11 + Microsoft Edge + Node 24 / pnpm 11；DSH `0.2.1-rc.2`；开发 profile 仅 `vibe-dev`
> 全量走一遍约 45–60 分钟（含抓包回放与可选密钥路径）
> 覆盖范围：HTTP 发送与取消、请求构建（query/headers/body/auth）、响应查看（JSON/HTML/图片/二进制/空体/大响应/重定向/4xx/5xx）、环境与变量、密钥引用、集合（保存/打开/改名/复制/删除）、历史（搜索/条数/打开/清空）、cURL 导入导出、OpenAPI 导入、断言、预览抓包回放、持久化与清理。
> 不重复验收：预览启动、帧率、输入、Console/Network 抽屉的基础行为属 M2；检查/标注页属 M3。API 页自身不依赖预览，只有抓包回放需要预览运行。

---

## 1. 一次性准备

### 1.1 构建插件

在仓库根目录 `<repo>`：

```cmd
cd <repo>
pnpm install
pnpm build
```

判断成功：输出里出现 `built lib\index.js` 和 `built lib\client.js`。

> DSH 运行中改代码后必须重新 `pnpm build`、重启 DSH 并刷新页面，否则加载的还是旧 `lib/client.js`。

### 1.2 确认插件已链接进开发 profile

```cmd
<DSH_BIN> --profile vibe-dev --dump-config | findstr vibe-studio
```

看到 `- id: vibe-studio` / `name: dsh-vibecode-studio` 即已就绪。若没有，执行一次：

```cmd
<DSH_BIN> plugin --profile vibe-dev add link:<repo>
```

> 不要装进 `desktop` / `web` profile。

### 1.3 准备一个会话

在 DSH 里新建或打开一个会话（真实或临时均可），右侧栏能打开 **Vibe Studio** 即可。API 页不使用 composer，M3 的“真实会话”限制在这里不适用。

### 1.4 面板宽度

把右栏拖到 **400–520px** 左右。API 页是纵向长列表（请求 → cURL → 检查 → 响应 → 环境 → 集合 → OpenAPI → 历史），窄于 400px 时按钮会换行，属预期。

## 2. 启动流程

需要**两个窗口**；抓包回放再确认 fixture 与预览。三个进程端口互不冲突：

| 端口 | 进程 | 用途 |
|---|---|---|
| 4317 | DSH Web（`vibe-dev`） | Studio 载体 |
| 4320 | fixture（`pnpm fixture:dev`） | 预览与抓包回放 |
| 4325 | M4 手测服务器（`tools/m4-manual-server.mjs`） | API 请求目标 |

### 窗口 1：M4 手测服务器（API 测试必开）

```cmd
cd <repo>
node tools\m4-manual-server.mjs
```

成功标志：输出 `[m4] listening on http://127.0.0.1:4325`。之后**每一次命中都会打印** `[m4] <METHOD> <URL>`，这是“有没有真的发出请求”的主要证据。

> 这个脚本只用于手测，不被产品代码引用；端口可用 `M4_PORT=4326` 覆盖，命令同 M3 一样在 cmd 里执行。不要用 `pnpm fixture:dev` 代替它——fixture 只有 `/api/echo`、`/api/boom`、`/api/slow`，缺少富响应体与状态码。

端点一览：

| 路径 | 行为 |
|---|---|
| `/api/json` | 200，嵌套 JSON（树、美化、分页） |
| `/api/count` | 200，每次递增 `{count}`，验证“只发了一次” |
| `/api/echo` | 回显 method、query、content-type、body、authorization、x-api-key、x-m4 |
| `/api/text` | 200，纯文本 |
| `/api/empty` | 204，无响应体 |
| `/api/html` | 200，HTML；内含 `<script>window.__m4xss = true</script>`，预览里必须不执行 |
| `/api/image` | 200，96×64 PNG 渐变图 |
| `/api/binary` | 200，`application/pdf` 小文件 |
| `/api/headers` | 200，带响应头 `x-m4-header`、`cache-control` |
| `/api/status/404` | 404 JSON |
| `/api/status/500` | 500 JSON |
| `/api/redirect` | 302 → `/api/json` |
| `/api/loop` | 302 指向自身（验证重定向上限） |
| `/api/slow?ms=3000` | 延迟 0–10000 ms 后返回 JSON |
| `/api/large` | 200，5 MiB JSON（超过执行器默认 4 MiB 上限） |

### 窗口 2：fixture（仅抓包回放需要）

```cmd
cd <repo>
pnpm fixture:dev
```

成功标志：`Local: http://127.0.0.1:4320/`。

### 窗口 3：DSH

```cmd
<DSH_BIN> --profile vibe-dev --no-open --host 127.0.0.1 --port 4317
```

成功标志：终端打印

```text
dsh web: http://127.0.0.1:4317/?token=<一串字符>
```

> 完全就绪前 DSH 不打印任何内容，等这行出现再操作，别重复开实例。

### 打开 Studio

1. 复制带 token 的完整 URL，在浏览器打开。
2. 右侧边栏点 **新标签页** → 选 **Vibe Studio**。
3. 顶部页签依次为 **预览 / 检查 / 标注 / API / 设置**，点 **API**。
4. 看到 **方法 / 地址 / 发送 / 保存** 和下方 **环境、集合、OpenAPI、历史** 即就绪。

## 3. 详细使用流程

> 每步都给出“预期”和可复制的 DOM 钩子。截图只作补充，不作为唯一证据。

### 3.1 第一条请求（GET /api/json）

1. 方法保持 **GET**，地址填 `http://127.0.0.1:4325/api/json`。
2. 点 **发送**。按钮先变 **发送中…**，随后下方出现响应面板。
3. 预期：
   - 状态徽标 `HTTP 200 OK`；
   - 元信息形如 `12 ms · 178 B`；
   - 响应体默认 **美化**，可切 **结构 / 原始**；
   - 窗口 1 打印 `[m4] GET /api/json`，**只有一条**。
4. 切到 **响应头**：可见 `content-type: application/json` 等，条数与图标上的数字一致。
5. 再点一次 **发送**：`/api/json` 不计数，但窗口 1 会多一条日志；若改打 `/api/count`，正文 `count` 应从 1 开始逐次加 1。

### 3.2 请求构建：查询、请求头、请求体、认证

API 页的请求分区在方法/地址下方，页签为 **查询参数 / 请求头 / 请求体 / 认证**。每行有 **启用** 勾选与 **删除这一行**；完全空的行不会发送。

**查询参数**

1. 查询参数加一行 `q` = `m4`，再点发送到 `/api/echo`。
2. 预期正文 `query` 为 `{"q":"m4"}`。
3. 取消该行 **启用** 后再发送，`query` 里不再出现 `q`。

**请求头**

1. 请求头加一行 `x-m4` = `header-ok`，发送到 `/api/echo`。
2. 预期正文 `customHeader` 为 `header-ok`。
3. 再加一行同名 `x-m4`，点发送：出现 **请检查请求** 与“请求头重复了”，且窗口 1 **没有新日志**。

**请求体**

1. 方法改 **POST**，请求体类型选 **JSON**，填 `{"hello":"m4"}`，发送到 `/api/echo`。
2. 预期正文 `contentType` 为 `application/json`，`body` 为这段 JSON。
3. 把 JSON 改成 `{bad`：出现“请求体不是合法的 JSON”，0 请求。
4. 类型换 **文本**，内容 `plain-m4`，内容类型 `text/plain`：回显 `contentType: text/plain`、`body: plain-m4`。
5. 类型换 **表单（urlencoded）**，加字段 `a=1`、`b=2`：回显正文是 `a=1&b=2`。
6. 类型换 **多部件表单**，加字段 `note=m4`，再 **添加文件**、字段名 `file`、选一个**小于 64 KB** 的本地文件（如仓库里的 `package.json`）：发送成功，回显正文含 `multipart/form-data` 与文件内容。
7. 选一个大文件（> 64 KB）：发送前就提示超过面板传输上限（64 KB）——这是 unary 通道上限，不是文件 4 MiB 上限。

**认证**

1. 认证选 **Bearer 令牌**，令牌填 `demo-token`，发送到 `/api/echo`：回显 `authorization: Bearer demo-token`。
2. 选 **Basic**，用户名 `u`、密码 `p`：回显 `authorization: Basic dTpw`。
3. 选 **API Key**，键名 `x-api-key`、键值 `k1`、位置 **请求头**：回显 `apiKey: k1`；位置改 **查询参数**：回显 `query` 里出现 `x-api-key=k1`。
4. 令牌留空点发送：出现“请输入 Bearer 令牌”，0 请求。

**校验与取消**

1. 地址清空 → 发送：“请输入地址”，0 请求。
2. 地址填 `ftp://127.0.0.1/x` → “请使用 http:// 或 https:// 开头的绝对地址”。
3. 地址填 `http://u:p@127.0.0.1:4325/api/echo` → “地址里不要带账号密码”。
4. 地址填 `http://169.254.169.254/` → 发送后显示 **Host 拦截了这个目标**，窗口 1 无日志（执行器拒绝链路本地地址与元数据主机）。
5. 地址填 `http://127.0.0.1:4325/api/slow?ms=10000`，点发送后立刻点 **取消**：状态行出现 **已取消。**；窗口 1 仍会打印该请求（请求已离开 Host，取消是客户端中止）。

### 3.3 响应查看与富响应体

发送后响应面板在请求表单下方、环境面板上方。页签 **响应体 / 响应头**，正文模式按内容类型变化：

| 地址 | 预期 |
|---|---|
| `/api/json` | 默认 **美化**；**结构** 是 JSON 树，点节点展开/折叠；**原始** 是纯文本；元信息有耗时与字节数 |
| `/api/text` | 只有原始文本 |
| `/api/html` | 默认 **预览**；页面显示 “M4 HTML preview”，脚本不得执行（不会弹窗、无 `__m4xss` 副作用）；**原始** 显示 HTML 源码；预览上方提示已禁用脚本、表单和网络 |
| `/api/image` | 直接显示 96×64 渐变图（1×1 时几乎看不见，现在应能看到方块渐变） |
| `/api/binary` | 显示 **二进制响应体（… 字节），该类型暂无内联预览。** 与 **下载** 按钮；下载文件应为可打开的 PDF |
| `/api/empty`（204） | 显示 **响应没有响应体。**，不显示空文本框 |
| `/api/status/404`、`/api/status/500` | 状态徽标分别为 `HTTP 404 …` / `HTTP 500 …`；**这不是错误面板**，正文照常显示 |
| `/api/redirect` | 元信息出现 **1 次重定向**，正文是 `/api/json` 的内容 |
| `/api/loop` | 发送失败，提示 **请求未能完成**（重定向次数达到上限，不出响应面板） |
| `/api/large` | 状态 200，正文前出现 **已按大小上限截断**；JSON 不再美化，提示 **响应体过大，无法美化，显示原始文本**；正文分页，**下一页 / 上一页** 与“第 1 / N 页”可用 |
| `/api/headers` | 响应头里能找到 `x-m4-header: visible-in-headers-tab` 与 `cache-control: no-store` |

结构化边界：

- JSON 树最多渲染 2000 个节点、16 层；超出时显示“结构树在 N 个节点处截断 / 嵌套超过 N 层的内容已折叠”，属上限而非解析失败。
- 美化解析上限 256 KiB 字符；执行器默认只取 4 MiB 响应体（上限 16 MiB，当前 UI 不暴露），超过即截断徽标。
- 响应头中命中敏感名的值会显示为由 Host 脱敏；`/api/headers` 的 `cache-control` 不在敏感名单，应保持原样。

### 3.4 环境、变量与密钥（FR-API-04）

环境面板在响应面板下方，默认就是一个**可编辑**面板：顶部 **环境** 选择器（含 **不使用环境**）、**新建**、**名称**，其下是变量行与 **添加变量 / 保存 / 删除**。

**建立并使用环境**

1. 点 **新建**，名称填 `M4 本地`。
2. **添加变量**，建两行：
   - `baseUrl` = `http://127.0.0.1:4325`（不勾密钥）；
   - `note` = `from-env`（不勾密钥）。
3. 点 **保存**：状态显示 **已保存。**，选择器出现 `M4 本地`，标题旁显示 **用于发送 · &lt;id&gt;**。
4. 请求地址填 `{{baseUrl}}/api/echo`，请求头加 `x-m4: {{note}}`，发送。
5. 预期：回显 `customHeader: from-env`，`path: /api/echo`；**没有**“未解析变量”块。
6. 只改环境里的 `note` 但不点保存，再发送：仍用旧值（发送读的是 Host 里已保存的环境）。面板会显示 **未保存**。
7. 环境选择器切 **不使用环境** 再发送：`{{baseUrl}}` 原样保留，回显里能看到字面量；发送后出现 **未解析变量** 块，列出 `baseUrl（url）未定义`。
8. 变量行的 **启用** 取消后再发送：同样进入未解析块，原因显示 **已停用**。

**密钥引用（可选，但建议至少跑“未配置”路径）**

环境从不保存密钥值：勾选 **密钥** 后，这一行的“值”要填 **DSH 凭据名**，不是密钥本身。凭据名规则：字母/数字/下划线，不能以数字开头，不能有点或连字符。

先跑未配置路径：

1. 再添加变量 `missingToken`，勾 **密钥**，值填 `M4_TEST_MISSING_REF`。
2. 保存环境：该行旁显示 **未配置**；密钥行下方出现提示“密钥变量填写凭据名称；值只保存在 Host 上，这里不会显示。”
3. 请求头加 `x-m4: {{missingToken}}`，发送：回显 `customHeader` 为字面量 `{{missingToken}}`；发送后 **未解析变量** 块列出 `missingToken（headers）密钥未配置`。

若要跑“已配置”路径，用**专用测试值**，不要用真实 API Key：

```cmd
set M4_TEST_TOKEN=m4-test-value-123
<DSH_BIN> --profile vibe-dev --no-open --host 127.0.0.1 --port 4317
```

> 两行必须在**同一个 cmd 窗口**里执行；`set` 只对这一终端启动的 DSH 生效，关掉终端即消失，不写系统环境变量。DSH 启动时会取当时的环境快照，启动后再 `set` 不生效。若 DSH 已在运行，需要先关掉再用上面的命令重启。

4. 环境里添加 `token`，勾 **密钥**，值填 `M4_TEST_TOKEN`；保存后应显示 **已配置**（与 `missingToken` 的 **未配置** 并列）。
5. 请求头改成 `x-m4: {{token}}` 发送：回显 `customHeader: m4-test-value-123`；未解析块消失。
6. 地址改成 `{{baseUrl}}/api/echo?token={{token}}` 发送：回显 `query.token` 为测试值；**响应体是目标返回的数据，不会脱敏**（见 §6）。
7. 点 **保存** 把这条请求存进集合，再从集合打开它：请求头/地址里仍是 `{{token}}`，**不是**明文；历史里打开也一样。这是 R1 在手动侧最直接的“不落盘、不回显到存储”证据；Host 最终 URL 的脱敏由 R7 证据脚本覆盖。

**删除环境**

- 选中一个已保存环境，点 **删除**：立即移除，**没有二次确认**，也没有撤销。手测时只删自己新建的 `M4 本地`。

### 3.5 集合：保存、打开、改名、复制、删除（FR-API-05）

集合面板在环境面板下方。**保存** 是单击操作：把当前请求**追加**到名为 **已保存的请求** 的默认集合，并自动展开该集合。

1. 用 3.1 的 `/api/json` 请求点 **保存**：状态 **已保存。**，集合树出现 **已保存的请求**，展开后有一条 `GET /api/json`。
2. 点这条请求：表单被填入，出现 **已载入保存的请求。点“发送”之前不会发出任何请求。**；窗口 1 **没有新日志**。
3. 再点一次 **保存**：默认集合里出现第二条同名 `GET /api/json`（保存不查重）。
4. 集合行点 **重命名**：输入 `M4 手测集合`，按 **Enter** 或点 **保存**；Esc 取消。空名时保存按钮禁用。改名后刷新页面（F5），名称仍在。
5. 改名后再点请求的 **保存**：新请求仍追加到这个（已改名的）默认集合，而不是新建一个。
6. 点集合行的 **复制**：出现副本 `M4 手测集合 copy`（后缀就是英文 `copy`），副本自动展开，请求数与源一致；在副本里删除/改名不影响源集合。
7. 点 **删除**：出现确认框 **删除这个集合？**，正文写明“内容会从本项目删除，无法撤销”；点 **删除** 才生效，点 **取消** 保留。
8. 刷新页面：改名、复制、删除的结果都保持（`.vibe/api/collections` 落盘）。

> 保存只存**请求**，不存响应；导入 OpenAPI 生成的集合不是“保存”的目标，只能打开其中的请求后再保存到默认集合。

### 3.6 历史：搜索、条数、打开、清空（FR-API-06）

历史面板在最下方。每次发送（成功或失败）都会记录一条；失败记录可能没有状态码与耗时。

1. 连续发送几条不同请求（`/api/json`、`/api/status/500`、`/api/count`）。
2. 预期：每条显示方法、URL、`状态 · 耗时 · 时间`，右侧 **打开**；顶部数字是**总数**，不是当前显示条数。
3. 搜索框输入 `500`：只剩 500 的那条；输入 `zzz`：显示 **没有匹配的请求**；点右侧 **清空搜索** 恢复。
4. 顶部 **显示条数** 选 `50`（默认）/`100`/`200`：列表最多显示这么多条；当总数大于显示条数时，底部出现 **还有 N 条更早的请求未显示。**
5. 点某条的 **打开**：表单填入，出现 **已从历史载入请求。保存时已去掉密钥值；点“发送”之前不会发出任何请求。**；窗口 1 无新日志。
6. 点 **清空历史** → 确认框 **清空发送记录？** → **清空**：列表变空，集合不受影响。
7. 刷新页面：清空前历史与集合都在；清空后历史为空（`.vibe/api/history.json`）。

### 3.7 cURL 导入与导出（FR-API-07）

点请求表单下方的 **cURL** 展开面板。导入只填表单，不发送；变量占位符 `{{name}}` 原样保留，等到发送时才解析。

**导入**

1. 粘贴：

   ```text
   curl 'http://127.0.0.1:4325/api/echo' -X POST -H 'content-type: application/json' -H 'x-m4: from-curl' -d '{"hello":"curl"}'
   ```

2. 点 **填入表单**：方法变 POST、地址与两个请求头、JSON 正文都进入表单；出现载入提示；窗口 1 **没有新日志**。
3. 点 **发送**：回显 `customHeader: from-curl`、`body` 为 `{"hello":"curl"}`。
4. 导入带 `-u user:pass` 的命令：表单进入 **Basic** 认证；`-H 'Authorization: Bearer {{token}}'` 会保留占位符。

**导出**

1. 表单完整时，同一面板下方出现 **当前请求对应的命令**。
2. 点 **复制**：显示 **已复制。**；粘贴到文本编辑器，应含 `-X`、`-H`、`-d`（或 `-F`）与完整 URL；`{{name}}` 保持原样。
3. 有附件文件时，导出命令**不带附件**，并列出丢失去向（例如“命令不含附件文件，只带上其余字段。”）。

**错误路径**

| 输入 | 预期 |
|---|---|
| 空文本点填入 | 请先粘贴 cURL 命令 |
| `curl`（无 URL） | 命令里没有 URL |
| `curl 'http://x' -Q` | 未知参数：`-Q` |
| `curl 'http://x' -F 'file=@a.txt'` | 暂不支持上传文件（`@a.txt`） |
| 引号未闭合 | 有引号没有闭合 |
| 超过 64 KB | 命令太长，面板上限 64 KB |

### 3.8 OpenAPI 导入（FR-API-08）

集合面板下方的 **OpenAPI** 折叠面板。Host 解析文档并生成**一个新集合**，全程不发请求。

1. 展开 **OpenAPI**，粘贴下面的文档（服务器指向手测服务器）：

   ```json
   {
     "openapi": "3.0.3",
     "info": { "title": "M4 Manual API", "version": "1.0.0" },
     "servers": [{ "url": "http://127.0.0.1:4325" }],
     "paths": {
       "/api/json": { "get": { "tags": ["items"], "responses": { "200": { "description": "ok" } } } },
       "/api/status/404": { "get": { "tags": ["status"], "responses": { "404": { "description": "missing" } } } }
     }
   }
   ```

2. 点 **导入**：显示 **已导入 2 个端点、2 个分组，集合名为“M4 Manual API”。** 与 **打开一条请求并点“发送”之前，不会发出任何请求。**
3. 集合树自动展开新集合，出现分组 `items` / `status`，条目名形如 `GET /api/json`、`GET /api/status/404`。
4. 点 `GET /api/json`：表单填入，载入提示出现；窗口 1 无日志。
5. 点 **发送**：`200 OK`，正文与 3.1 相同。
6. 再点一次 **导入**（同一文档）：生成**另一个**集合，不覆盖原集合（id 自动加后缀）。
7. 错误路径：
   - 空文本 → 请先粘贴文档或选择文件；
   - 非 JSON → 文档不是合法的 JSON；
   - `{"openapi":"3.0.0"}`（缺 info/paths）→ 这不是可用的 OpenAPI 3.x 或 Swagger 2.0 文档；
   - 文档里含远程 `$ref` → Host 阻止远程引用（`remote_ref_blocked`），不发起网络请求；
   - 文本超过 64 KB → 文档太大，单次导入上限 64 KB（这是 unary 通道上限，不是导入器自身的 8 MiB）。
8. **选择 JSON 文件** 与粘贴等价；文件 ≥ 64 KB 时在本地就被拒绝。

### 3.9 断言（FR-API-09）

请求表单下方的 **检查** 面板，支持四种内置检查：**状态码 / 响应头 / JSON 字段 / 耗时**；比较方式 **等于 / 包含**。不发脚本。

1. 添加四条检查：
   - 状态码 = `200`；
   - 响应头 `content-type` 包含 `application/json`；
   - JSON 字段 `$.ok` 等于 `true`；
   - JSON 字段 `$.items[0].name` 等于 `alpha`。
2. 发送 `/api/json`：标题旁显示 **通过 4/4**，每条显示通过；窗口 1 只有一条日志。
3. 把状态码改成 `201` 再发送：该条失败并显示“期望状态码 201，实际 200。”，其余仍通过（3/4）。
4. 状态码填 `abc` 或 `20`：提示“状态码须为三位数字（100–599）”，**0 请求**。
5. JSON 路径填 `items`（不以 `$` 开头）或超过 200 字符：提示“JSON 路径以 $ 开头，最长 200 个字符”，0 请求。
6. 发送后改任意一行：上一轮的通过/失败结果立即消失（避免把旧结论挂在新请求上）。
7. 断言不落盘：保存请求、刷新、从集合或历史打开，检查列表为空。

已知限制（设计如此）：JSONPath 仅支持 `$.a.b[0]` 这类路径，不支持通配、递归、过滤、切片；数字按文本比较（`200` ≠ `200.0`）；Host 在响应体按 4 MiB 截断后求值。

### 3.10 抓包回放（FR-API-10）

前置：fixture（4320）与 DSH 均已启动，**预览** 页签里地址填 `http://127.0.0.1:4320` 并点 **启动**。

1. 预览运行后，打开 **网络** 抽屉（预览工具栏的 **网络** 按钮）。
2. **先打开抽屉，再点预览工具栏的刷新**，或在 fixture 里点一次按钮。原因见 §6：采集器在会话建立后才挂上，首次文档加载可能抓不到。
3. 抽屉里出现条目；点一条 **POST /api/echo** 展开详情（请求头、响应头、请求体/响应体）。
4. 点 **回放**：
   - 非只读方法先弹确认 **回放 POST？**，正文写明可能改变目标数据；点 **回放 POST** 才继续；
   - 点 **取消** 不产生任何草稿。
5. 确认后自动切到 **API** 页签，表单被填入，出现 **已从抓包载入**：来源 `来自 POST …`、`还没有发送…`、必要时列出被省略的头、被截断的 body、被脱敏的 query、16 KB body 限制。
6. 此时窗口 1 **没有新日志**——回放只载入草稿，不发送。

8. 回放一条 **GET** 条目：不弹确认，直接载入。

预期警告：`Cookie`、`Authorization` 等头会被省略（提示通过认证或环境补上）；捕获的 URL 中敏感 query 会显示为脱敏值，需要时改成 `{{变量}}`；超过 16 KB 的请求体会截断并提示。

## 6. 正常但容易误判的现象

- **404/500 不是“出错”**：只要拿到响应就显示响应面板；只有网络失败、拦截、超时、重定向超限才显示错误块。
- **响应体里的密钥是目标返回的数据**：R1 只清洗最终 URL 与重定向 hop，不重写响应体。测试服务器把请求头/query 原样回显，所以会看到解析后的测试密钥——这是预期的“目标数据”，不是泄漏到 URL。
- **最终 URL 不在 UI 里展示**：响应面板只显示重定向次数，不显示最终 URL，所以“URL 脱敏”在手动侧看不到；由 R7 证据脚本覆盖（`outcomeHasSecret:false`）。
- **保存/历史只存占位符**：`{{token}}` 原样落盘，打开后看到的是占位符；这不是“没保存”。
- **保存永远追加到默认集合**：默认集合被改名后，新请求仍进这个集合；保存不查重，会看到同名多条。
- **导入集合不会被“保存”追加**：OpenAPI 集合只读（通过 UI）；要改就打开条目再保存到默认集合。
- **复制名带英文 `copy`**：复制结果形如 `已保存的请求 copy`，即使界面是中文，属现状。
- **重复导入不覆盖**：同名文档导入两次会得到两个集合，第二个 id 自动加后缀。
- **环境改了不保存不生效**：发送读的是 Host 里已保存的环境；面板显示“未保存”。保存后才切换/更新。
- **未解析变量块只在发送后出现**：它不是实时校验；变量定义缺失/停用/密钥未配置时，发送后才看到清单，且字面量 `{{name}}` 会被真的发出去。
- **密钥“已配置/未配置”只有两种**：面板不显示值，也不显示来源；值只存在 Host 的凭据 seam。
- **删除环境没有确认**：点 **删除** 立即生效，删前看清。删除集合有确认。
- **取消仍会到达服务器**：取消是中止客户端等待，Host 已经把请求发出；所以窗口 1 会有一条日志。
- **首次文档加载可能抓不到**：网络采集器在预览会话建立后才挂上；打开抽屉再刷新，条目才稳定出现。不是回放坏了。
- **回放从不自动发送**：只切页签、填表单，并给出提示；必须手动点 **发送**。
- **抓包请求体有 16 KB 截断、部分头被省略**：Cookie/Authorization 等由浏览器或 Host 省略，需要时用认证区或环境补；这是设计的安全边界。
- **cURL 导入不解析变量**：只填表，`{{name}}` 等发送时由 Host 展开。
- **断言结果会消失**：改任意检查行就清空上一轮结果；断言本身不落盘。
- **JSONPath 不是完整规范**：只支持简单路径；数字按文本比较；响应体截断后求值。
- **响应树有节点/深度上限**：2000 节点、16 层；大 JSON 看不到全量是上限，不是解析失败。
- **OpenAPI 64 KB 是通道上限**：导入器自身支持 8 MiB，但 unary 通道只允许 64 KiB 请求包，所以 UI 先拒绝。
- **`/api/large` 的 5 MiB 会被截断**：执行器默认只取 4 MiB；这是响应体上限，不是网络错误。
- **HTML 预览不执行脚本**：sandbox 禁用了脚本、表单和网络；页面上看到静态内容是预期。
- **多部件文件实际受 64 KB 通道限制**：文件本身允许 4 MiB，但请求包要过 unary，手测请用小文件。

## 7. 故障排查

| 现象 | 检查 |
|---|---|
| API 页空白 / 报错 | 是否 `pnpm build` 后重启 DSH 并刷新；插件是否链进 `vibe-dev`；浏览器 Console 是否有加载错误 |
| 发送提示“Host 拦截了这个目标” | 目标是链路本地/元数据主机；换 `127.0.0.1` |
| 发送提示“请求未能完成” | 4325 是否在跑；地址端口是否正确；窗口 1 是否有日志（无日志说明请求没离开 Host 或被拦截） |
| 发送提示“请求超时” | 默认 30 s；`/api/slow` 的 `ms` 是否过大 |
| 提示“请求超过了面板传输上限（64 KB）” | 请求体/文件/导入文档太大；换小文件或拆分文档 |
| 响应不出现但历史有记录 | 响应块在请求表单下方，向下滚动；确认不是在集合/历史面板里找 |
| 集合/历史显示“不可用” | `.vibe/api` 权限或越界；项目目录是否可写；重试或重启 DSH |
| 环境保存失败 | 环境名不能为空；变量名要符合 `[A-Za-z_][A-Za-z0-9_.-]*`；同名变量重复；密钥行的值必须是凭据名（字母/数字/下划线） |
| 密钥显示“未配置” | 凭据名是否拼对；`M4_TEST_TOKEN` 是否在启动 DSH 的同一终端里 `set`；启动后再设置不生效，需重启 DSH |
| 变量不展开 | 是否选中了该环境并已保存；变量是否启用；发送后看“未解析变量”块的原因 |
| OpenAPI 导入失败 | JSON 是否合法；是否 3.x/2.0；是否含远程 `$ref`；是否超过 64 KB |
| 抓包抽屉没有条目 | 预览是否运行；是否打开抽屉后刷新；页面是否有网络请求 |
| 回放按钮报错 | 条目是否过大；捕获是否缺少 body；是否非只读方法但没确认 |
| cURL 导入失败 | 看面板内的具体提示；附件、未知参数、引号、长度都有限制 |
| 端口被占用 | 4317/4320/4325 是否被上一轮残留；用 `netstat -ano | findstr` 查 PID，确认后结束 |
| 改了代码没生效 | `pnpm build` → 重启 DSH → 刷新页面 |
