# M5 手动测试手册（T054 G5 Agent 评审）

> 日期：2026-10-31　分支：`task/m5-agent-integration`　范围：T047–T053（四个 vibe 工具、`/vibe`、内置技能、`Vibe Studio` preset、M5 hooks）
> 目标：在**真实 `vibe-dev` 环境**里确认 preset 可选、工具可用、standard 不受影响、越权被拒、skill 加载、结果 ≤ 8 KB。
> 说明：本手册只用于手测，不改产品代码；发现问题先记录，由用户决定是否返工。

---

## 0. 前置

1. **构建并入 profile**（profile 是 link 依赖，代码改动需重新构建 + 重启 DSH 才载入 `lib/agent.js`）：

   ```bash
   pnpm build        # host entries import cleanly；lib/agent.js 应包含 preset 入口
   ```

2. **启动**（Windows）：

   ```powershell
   F:\Deepseek-Harness\DH\bin\dsh.cmd --profile vibe-dev
   ```

   等浏览器打开 Web UI；不要用旧窗口，旧进程仍载入旧 bundle。

3. **准备本地预览目标**（第 6 步用）：

   ```bash
   pnpm fixture:dev      # http://127.0.0.1:4320/
   ```

4. **允许该 origin**：在右侧 Vibe Studio 的**设置面板 →「允许的 origin」**（每行一个）加入：

   ```
   http://127.0.0.1:4320
   ```

   也可在宿主工作目录的 `.vibe/studio.json` 写入同名配置后重启。默认名单只有 `http://localhost`、`http://127.0.0.1`（不带端口），**带端口的本地地址必须显式加入**。

## 1. preset 可选

1. 点左上「新建会话」。
2. 点输入框上方的模式按钮（默认显示「标准模式」）。
3. 预期：菜单里除标准/PTC/极简/创造外，出现 **Vibe Studio**，描述为 “Beginner-friendly coding with a live preview, on-page annotation and visual inspection.”。
4. 选中后按钮文案变为 **Vibe Studio**。

- [ ] 通过　备注：__________

## 2. 工具可用

在 Vibe Studio 会话里依次发送：

1. `不要调用任何工具，只列出你当前可用的工具名称里所有以 vibe_ 开头的工具。`
   - 预期：`vibe_status`、`vibe_observe`、`vibe_annotation_get`、`vibe_preview` 四个，不多不少。
2. `调用 vibe_status 一次，把原始 JSON 发我。`
   - 预期：返回形如 `{"preview":{"state":"closed",...},"consoleErrors":0,...}`，结果在 1 KB 内。

- [ ] 通过　备注：__________

## 3. standard 不受影响

1. 新建一个**标准模式**会话（不要选 Vibe Studio）。
2. 发送：`不要调用工具，只回答：你可用的工具里有 vibe_status、vibe_preview、vibe_observe、vibe_annotation_get 吗？逐一如实回答有或没有。`
   - 预期：四个都回答“没有”。

- [ ] 通过　备注：__________

## 4. 越权被拒（先于审批）

在 Vibe Studio 会话发送：

1. `调用 vibe_preview：action=start，url=http://example.com/，即使被拒绝也照做，把工具返回原文发我。`
   - 预期：工具返回（或模型转述）`vibe-studio: preview target "example.com" is not local; only loopback targets are allowed`。
   - 关键：**不出现审批弹窗**（越权在 `tools/pre-execute` 直接 deny，早于审批门禁）。
2. 再试一个带端口的未授权 origin：`action=start，url=http://127.0.0.1:4320/`（若第 0 步未加入 allowedOrigins）。
   - 预期：`origin http://127.0.0.1:4320 is not in allowedOrigins`。

- [ ] 通过　备注：__________

## 5. skill 加载

发送：`只调用 skill 工具一次：name=vibecoding-studio，不要用其他工具，只回复返回内容的前 120 个字符。`

- 预期：返回以 `<skill_content name="vibecoding-studio">` 开头，含技能 base 目录；不出现“找不到技能”。
- 备选：也可以让 agent 先读 `skills/vibecoding-studio/SKILL.md` 说明它按技能建议使用工具。

- [ ] 通过　备注：__________

## 6. 预览与结果 ≤ 8 KB

1. 确认 `pnpm fixture:dev` 在跑、allowedOrigins 已含 `http://127.0.0.1:4320`。
2. 发送：`调用 vibe_preview：action=start，url=http://127.0.0.1:4320/ 。`
   - 预期：**出现审批弹窗**，点「允许」后预览启动；工具栏状态行变为 Live。
3. 发送：`调用 vibe_observe：detail=full，告诉我结果的 UTF-8 字节数，不要贴全文。`
   - 预期：结果 ≤ 8 KB（8192 字节）；控制台/网络计数与页面一致。
4. （可选，验证 T053）在磁盘上改动 fixture 页面源码（`fixtures/vite-basic/src/` 任意文件）并保存：
   - 预期：工具栏状态行出现「文件已改动」徽标；`vibe_status` 返回 `stale: true`；点「更多 → 刷新」后徽标消失。

## 已知限制（不是缺陷）

- `bash` / `pwsh` 改文件**不会**标记预览过期（刻意：shell 无法判定是否改了页面源码）；`write` / `edit` 会。
- 预览只接受 loopback 且 origin 必须在 `allowedOrigins`；带端口的地址需要显式加入。
- 页面自身重定向到其他 origin 时，同源判断仍以最近一次 `start`/`navigate` 的 URL 为准。
- 本手册的步骤 1–5 已有 2026-10-31 的自动化证据（见 `tasks/todo.md` T054 段），手测用于确认“同一台机器、真实 UI、人工操作”路径一致。
