# 验证接口对接说明（`preview.verify.run`）

> 状态：已实现（M6 / T055–T056，分支 `task/m6-verify-hardening`，未推送、未合并）
> 适用：客户端 UI（验证面板）、后续 agent 工具或第三方接入方
> 关联：T055 服务实现 `src/host/verify/{checks,service}.ts`、T056 面板 `src/client/verify/VerifyPanel.tsx`

## 1. 定位

一次**只读**验证：读取当前预览会话的状态、最小 DOM 摘要与两个有界缓冲区，评估四项基础检查——**目标在线 / 页面可加载 / 无 console error / 无失败请求**——返回固定 schema 的结果。不启动、不刷新、不导航、不改会话。

服务端能力：`VibeStudioService.verify.run()`（`src/host/verify/service.ts`）。
客户端唯一入口：一元方法 `preview.verify.run`（`src/contracts/transport.ts`）。

## 2. 传输约定

沿用 T011 的 unary 传输，不新增路由：

```
POST /api/vibe/request
content-type: application/json

{ "id": "<可选，回调关联 id>", "method": "preview.verify.run" }
```

- **无参数**：不接受 `params`；传了也会被忽略（服务签名无入参）。
- 成功：HTTP 200，`{ ok: true, id?, value: VerifyResult }`。
- 失败：HTTP 200 仍是“验证跑完”的语义（结果里 `ok:false`），只有**传输层**故障才走错误信封：
  - 方法未注册 → 404 `not_found`
  - 请求体/方法名非法 → 400 `invalid_input`
  - 请求体超过 64 KiB → 413 `invalid_input`
  - 处理器抛异常 → 500 `internal`（正常情况下 `run()` 不抛）
- 可重复调用；并发调用互不影响（每次都是只读快照）。

客户端示例：

```ts
import { PREVIEW_VERIFY_RUN_METHOD } from '../contracts/transport'
import { callUnary } from '../transport/client'

const result = await callUnary<VerifyResult>(PREVIEW_VERIFY_RUN_METHOD)
```

## 3. 响应形状

```ts
interface VerifyResult {
  ok: boolean                    // 四项全部 pass 才为 true
  ranAt: string                  // ISO 时间，取“结束时刻”
  durationMs: number
  url: string | null             // 当前预览 URL（已脱敏）
  checks: VerifyCheck[]          // 固定 4 项，顺序 target→page→console→network
  consoleErrors: number | null   // null = 采集不可用
  failedRequests: number | null  // null = 采集不可用
  truncated: boolean             // 证据被裁剪过（计数仍然完整）
}

interface VerifyCheck {
  id: 'target' | 'page' | 'console' | 'network'
  status: 'pass' | 'fail' | 'skipped'
  message: string                // 人读的一句话
  evidence?: VerifyEvidence[]    // 最多 5 条，仅 console/network 检查会有
}

type VerifyEvidence =
  | { kind: 'console'; id: string; level: string; text: string }
  | { kind: 'network'; id: string; method: string; url: string; status: number | null; outcome: string }
```

语义要点：

| 情况 | 表现 |
|---|---|
| 预览未启动 / 已停止 / 崩溃 | `target` fail，其余 `skipped`，两个计数 `null` |
| 页面无 DOM 节点 | `page` fail（`nodeCount < 1`） |
| 采集能力不可用 | 对应检查 `skipped`，计数 `null`，不谎报通过 |
| 有 console error / 失败请求 | 对应检查 fail，附最多 5 条证据 |
| 结果超预算 | 先丢尾部证据，再收紧消息（120/60/24 字），最后清空消息；`truncated: true` |

**失败请求判定**：`outcome === 'error'` 或 `status >= 400`；`aborted` 与 pending 不算。定义与 `vibe_status` / `vibe_observe` 共用（`src/contracts/telemetry.ts` 的 `isNetworkFailure`）。

**大小预算**：整个结果 ≤ 4096 B（UTF-8、合法 JSON）。默认一次实测约 620 B。

## 4. 证据与跳转约定（UI 对接）

- 证据 id 就是采集缓冲区的行 id：`console-N` / `network-N`；同一次运行内唯一，可在对应抽屉里按 `data-entry-id` 定位。
- 跳转契约：`onOpenEvidence(evidence)` → 打开 `evidence.kind` 抽屉 → 该抽屉按 `{ id, nonce }` 只揭示一次：切过滤到 `all`、`scrollIntoView({block:'center'})`、高亮 2 s。高亮期间暂停“自动滚到底”，避免新事件把证据行顶走。
- 面板不复制抽屉的格式化逻辑：证据按钮文案只是 `level · text` 或 `METHOD url → status`。

## 5. 界面（T056 参考实现）

- 位置：预览页底部抽屉的第三个页签（`Verification`），与 Console / Network 同层，常驻挂载、按 `visible` 切 `display`。
- 结构（保持简洁）：标题 + `Run checks`；一行状态（汇总 · 运行时刻）；四行检查（符号 + 名称 + Host 消息）；失败行的证据按钮；裁剪提示。
- 状态词（通过/未通过/跳过）不占正文，放进每行的 `aria-label`。
- 预览未启动：页签仍可打开，`Run` 禁用并提示先启动预览。
- 传输错误：`role="alert"`，保留上一次结果。
- 稳定选择器：`[data-vibe-verify="1"]`、`[data-vibe-verify-check]`、`[data-status]`、`[data-vibe-verify-evidence]`、`[data-evidence-id]`、`[data-vibe-verify-toggle]`。

## 6. 已知口径（对接时别误用）

- 检查覆盖**缓冲区全量**（页面加载以来），不是“本次运行后新增”。要干净的一次，先 Reload 或清空两个抽屉再运行。
- `ok:false` 不区分“环境问题”和“页面问题”，看 `checks[].status` 与 `message`。
- 计数与证据是两套口径：`truncated: true` 只说明证据被裁剪，`consoleErrors` / `failedRequests` 仍是完整计数。
- 面板不再展示耗时与缓冲区说明（页面简洁要求）；需要这些细节时直接看 `durationMs` 字段或文档。

## 7. 安全

- 所有 `message` / `text` / `url` 来自页面，按**不可信文本**渲染（只作文本节点，不拼 HTML）。
- URL 与 header 在采集层已脱敏；不含密钥。
- 接口只读、无副作用，不触发审批；预览启停仍走 `vibe_preview` 的门禁（`permission_denied` + 审批）。
