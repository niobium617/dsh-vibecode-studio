## 2. 最终决策

### 2.1 帧传输：stream 为主，pull 为回退

**选择：**

- 默认通道：`GET` 文档相对路径 `api/vibe/stream`，`multipart/x-mixed-replace`，每帧携带 `seq`、host 时间戳与 host RSS。
- 回退通道：`GET` 文档相对路径 `api/vibe/frame`，返回最新 JPEG，携带 `x-vibe-seq` / `x-vibe-ts`。
- 两条通道共用帧格式、seq 语义、健康检查与指标路由；上层接口不因切换而变。
- 客户端必须使用**文档相对路径**（`api/...`，不带前导 `/`），否则 Desktop 的 `dsh-app://app/` 协议处理器不会把请求转发给 host。

**理由：** S1 在 Web 与 Desktop 均为 30 fps、0 gap；stream 延迟更低（Web 1.0 vs 2.7 ms，Desktop 1.6 vs 3.1 ms），10 min soak 无断流、内存稳定。

**回退触发（由 T020 实现并验证）：**

- stream 结束/异常后 500 ms 重连；连续重连失败或长时间无新帧时切到 pull。
- pull 在非 2xx 时退避 250 ms、请求异常时退避 300 ms。
- host 重载后 seq 会重置为 1；pull 的 `after` 高水位必须能检测“连续 200 但 seq 不前进”并重新同步，或直接切回 stream。S1 未模拟该场景，列为 T020 必测项。
- 恢复后优先回到 stream，不长期停留在 pull。

**帧节奏：**

- 目标 30 fps；T020 必须做限速（`Page.startScreencast` 的 `everyNthFrame` 或 host 侧按时间片限量）。
- S3 的上限约 98 fps、20.2 KB/帧（≈ 2.0 MB/s）；30 fps 时约 0.6 MB/s，是产品的默认带宽预算。
- Windows 定时器粒度约 15.6 ms，30 fps 调度必须用 deadline scheduler，不能依赖裸 `setInterval(33)`。

### 2.2 输入：CDP 一元请求，独立于帧通道

**选择：**

- 点击、滚轮、键盘、文本提交走精确 fetch 的一元请求，由 host 调用 CDP `Input.*`；不逐帧往返。
- 指针悬停/高亮由页面内拾取脚本处理，不走 host 往返。
- 输入通道与帧通道分离，避免帧背压阻塞输入。

**依据与边界：** S3 测得 CDP 派发到页面事件/绘制为 1–27 ms（最大为滚轮），远低于 200 ms 验收线；但该数字是页面内延迟，不含“DSH client 点击 → host HTTP → CDP”。T021 必须实测端到端，不可复用 S3 数字作为验收证据。

### 2.3 中文 IME：客户端组合 + host `insertText`，失败走逐字/粘贴

**选择（主路径）：**

1. 客户端用隐藏 textarea 承接真实系统输入法。
2. 在 `compositionend` 时把已提交文本发给 host。
3. host 用 CDP `Input.insertText` 写入 preview 的当前焦点元素。
4. 不回放组合过程的每个中间态；页面不需要自己实现 IME。

**依据：** S3 验证了 `Keyboard.insertText('你好，世界')`、逐字 `Keyboard.type('中文')`、CDP 模拟 IME（`compositionstart/update/end`、`isComposing`）三条路径均正确，焦点/Tab/Esc 正常。

**条件性验证（T022）：**

- 用 Microsoft Pinyin 在 Web 与 Desktop 各手测一次“你好，世界”。
- 通过则维持主路径；失败则启用回退。

**回退（最终选择）：**

- 逐字发送按键，或提供“粘贴文本”入口。
- UI 明示“中文输入受限，可用外部浏览器打开”。
- 不使用 `ctx.webServer`，不把输入法事件绕过 `ctx.connection`。

### 2.4 截图：复制到剪贴板 + 用户手动粘贴

**选择（最终）：**

- MVP 只提供“复制截图（PNG）到系统剪贴板”，由用户手动粘贴到 composer。
- 不调用 `createDrafts` / `addAttachments`，不依赖非公开 `IConversation` 方法，不自动附加、不自动发送。
- 文本复制作为同样可用的回退；标注文本本身必须自包含，不能因图片不可用而丢失信息。

**依据：** S2 在 Web/Desktop 均验证 `navigator.clipboard.writeText` 与 `ClipboardItem({ 'image/png': file })` 可用；`createDrafts` 不在公开 `IConversation`，且附件 id 在会话切走再切回后丢失。

**未来条件：** 仅当 DSH 公开附件创建/释放 API 且经复测（含跨会话保留、失败清理、发送序列化）后，才重新评估直接附件；当前不排期。

### 2.5 源码：按框架适配，拿不到就明确降级

**选择（最终顺序）：**

1. 构建期属性（React 19+）：`data-inspector-relative-path` / `-line` / `-column`，由开发态 Babel 插件注入。
2. 框架运行时：Vue 读 vnode 的不可枚举 `__v_inspector` 或 `__vue_inspector_store__.vnodeToPos`；Svelte 读元素 `__svelte_meta`。
3. 无源码降级：只给选择器 + DOM 摘要，并明确标记“源码信息不可用”，不猜测文件/行号。

**统一契约：** 适配器输出 `{ framework, via, file, line, column }` 或 `null`；`file` 为项目相对路径。

**边界与要求：**

- 仅开发模式提供源码；生产构建不注入、不承诺源码定位，UI 明确提示。
- React 18 的 `_debugSource` 只作为可选旧版兜底，不作为 React 19+ 的依赖。
- Vue 不得依赖 `el.closest('[data-v-inspector]')`；运行时属性已被移入 vnode。
- Svelte 缺失 `__svelte_meta` 时走第 3 步。
- 构建期注入作为项目显式选项，默认仅 dev 开启；正式实现需补 `.tsx` 覆盖与成本评估（S4 只测了 `.jsx`）。
- 选择器必须实时校验唯一性；失败时退回多候选或 `tag:nth-of-type` 路径，不返回可能误命中的单一路径。
- overlay 使用 open Shadow DOM，宿主 `pointer-events: none`；拾取期间在捕获阶段拦截交互，但 `click` 由拾取器自己消费，避免拦截后自身监听失效。

**依据：** S4 三框架 30/30 命中、行号 delta=0、选择器唯一 30/30、点击泄漏 0；React 19 无 `_debugSource`、Vue 属性被移动到 vnode 是关键修正。
